# AiToEarn 对接 MARVIS Skill V2.0 + Hermes 调度协调完整方案

> 版本：V1.0  
> 日期：2026-06-22  
> 状态：方案文档，待落地  
> 依赖基线：MARVIS Skill V2.0（v2.0_release）

---

## 一、基础架构分层

| 层级 | 组件 | 职责 |
|------|------|------|
| 业务上层 | **AiToEarn** | 流量入口、订单分发、收益结算、用户任务管理、渠道分发，下发生产需求至 Hermes |
| 调度中台层 | **Hermes** | 统一任务分发、资源调度、任务状态监控、异常重试、算力配额管控，作为中间协调枢纽 |
| 底层执行层 | **MARVIS Skill V2.0** | 接单计价、热点匹配、精细化视频渲染、LUT 调色、合规质检、粉丝互动、定时运维清理，输出标准化任务结果/素材文件 |

---

## 二、AiToEarn ↔ Hermes 对接流程

### 2.1 任务下发链路（AiToEarn → Hermes）

1. AiToEarn 接收用户/渠道视频生产订单，组装标准化任务结构体：
   - 基础信息：订单 ID、赛道分类、粉丝量级（冷启动/成熟账号）、产出时长、营销文案素材
   - 管控参数：营销强度、LUT 调色风格、广告占比上限、互动自动回复开关、清理周期
   - 回调地址：任务完成/失败回调接口
2. AiToEarn 通过 HTTP/RPC 推送到 Hermes 任务队列，附带优先级标签（冷启动订单优先调度）
3. Hermes 校验任务参数合法性、分配空闲算力节点，标记任务状态 `pending`

### 2.2 结果回传链路（Hermes → AiToEarn）

1. MARVIS Skill 执行完成后，Hermes 收集产出：渲染视频、合规报告、互动日志、计价单据
2. Hermes 封装完整结果包，调用 AiToEarn 预设回调接口同步：
   - 成功：成品素材路径、合规校验得分、预估收益、互动执行统计
   - 失败：阻断节点（预审/渲染/QA）、错误日志、自动重试次数
3. AiToEarn 更新订单状态、完成收益核算、对外交付成品

## 三、Hermes ↔ MARVIS Skill V2.0 协调机制

### 3.1 环境部署隔离

- MARVIS 固定基线拉取：`git checkout v2.0`，所有执行节点统一使用封版稳定代码，禁止节点直接修改源码
- Hermes 多节点分发：多台机器统一拉取 GitHub 远端 `v2.0_release`，保证渲染、质检、互动逻辑全局一致
- 节点自动同步：启动节点时自动 `git pull` 基线，同步最新配置文件（LUT 调色参数）

### 3.2 任务调度与资源协调

**算力错峰管控**（Hermes 区分两类任务）：

| 类型 | 任务 | 调度策略 |
|------|------|----------|
| 重算力 | 视频渲染（LUT 调色、分层分辨率处理） | 凌晨低峰批量调度 |
| 轻算力 | 粉丝互动抓取、定时 30 天文件清理、预审计价 | 日间穿插执行，不抢占渲染资源 |

**定时任务统一托管**：

- 原 `task_cleanup_scheduler.py` 本地定时迁移至 Hermes 全局调度
- Hermes 统一触发过期素材/日志清理，控制执行窗口（凌晨 2-4 点）
- 清理日志统一汇总至 Hermes 监控面板，无需各节点单独维护日志目录

**异常容错协调**：

- MARVIS 渲染/QA 报错 → Hermes 捕获异常，根据错误类型自动重试（资源不足延时重试、参数错误直接驳回至 AiToEarn）
- 节点宕机：Hermes 自动将未完成任务重新分配至空闲节点，任务上下文持久化不丢失

### 3.3 配置统一同步机制

1. `filter_lut_config.json` 赛道调色配置统一由基线仓库管理
2. 配置更新后通过 `auto_push.bat` 推送 GitHub，Hermes 所有节点在下一轮任务启动时自动拉取新配置，全局画面风格同步更新
3. `.gitignore` 屏蔽所有本地临时日志，各节点仅回传关键业务报表至 Hermes 汇总，不产生冗余本地文件

## 四、三层交互完整数据流

```
AiToEarn（业务订单）
    ↓ HTTP/RPC 下发任务
Hermes（调度 / 算力 / 监控）
    ↓ 分发任务至执行节点
MARVIS Skill V2.0（渲染 / 质检 / 互动 / 计价）
    ↓ 产出素材、合规报告、统计日志
Hermes 汇总结果、清洗临时日志
    ↓ 回调推送成品与数据
AiToEarn 结算收益、交付用户
```

## 五、关键协调规则（避免冲突）

### 5.1 版本管控规则

- Hermes 所有执行节点强制锁定 `v2.0` Tag 基线
- 增值扩展（拓客/矩阵发布）需单独新开 feature 分支
- Hermes 切换分支灰度验证后再全量上线，不污染生产基线

### 5.2 日志统一管控

- MARVIS 本地禁止长期留存 `interaction_log` / `cleanup_logs`，执行完成后仅把核心统计数据上传 Hermes，本地临时文件自动清理
- GitHub Actions 仅作为版本备份，业务运行日志统一由 Hermes 集中存储

### 5.3 配置修改权限

- 仅本地通过 `auto_push.bat` 更新 `filter_lut_config.json` 等配置，推送远端后 Hermes 节点自动同步
- 禁止 AiToEarn、Hermes 直接修改 Skill 内部配置文件，统一走基线版本迭代

### 5.4 粉丝互动调度协调

- Hermes 控制评论抓取频次，限流避免平台风控
- 冷启动账号每日自动回复额度由 Hermes 统一管控
- 与 MARVIS 内部分层限流双重校验，防止账号风险

## 六、快速对接落地步骤

| 步骤 | 操作 |
|------|------|
| 1 | Hermes 节点批量拉取工程：`git clone https://github.com/yuanwu6666/skill.git && git checkout v2.0` |
| 2 | Hermes 封装调用 MARVIS 主入口 `demo_run.py` 作为标准化任务执行器，传入 Hermes 下发的任务 JSON 参数 |
| 3 | AiToEarn 对接 Hermes 任务推送与回调接口，统一订单字段规范 |
| 4 | Hermes 接管全局定时清理任务，停用单节点本地 `scheduler` |
| 5 | 全链路灰度测试：单节点跑通订单下发 → 渲染 → 质检 → 互动 → 结果回传，再扩容全节点 |
| 6 | 日常配置微调仅修改基线 JSON，自动推送 GitHub 后 Hermes 节点自动同步生效 |
